Stack · domain · code standards

Our rules,
checked every time.

We write rules for the tech we use, the goals of our domain, and how our code is laid out. zeno makes every request and every change follow them.

The model

Three kinds of rules, two checkpoints.

Tech stack

Pick the stack once. The rules come with it.

Current vendor docs

A pack indexes a vendor's own docs (expo, react, nextjs, firebase, revenuecat, uniwind ship today). The agent searches them instead of guessing an old API.

Import rules per repo

Each repo keeps its layers in .dependency-cruiser.cjs. A broken boundary or a cycle fails zeno check.

Our own checkers

Any script we already have (lint, schema check, design check) runs inside zeno check.

# company .claude/zeno.yaml, shared by every repo estate: true standards: [.zeno/standards] commands: - id: lint run: pnpm lint - id: designs run: ./scripts/check-designs.sh if: .context/designs # one repo's .claude/zeno.yaml kind: web modules: [docs, knowledge, code, architecture] packs: [nextjs, react, firebase]
Domain goals

The product's rules live in the repo, and the gate reads them.

DECISIONS

"No manual entry"

A decision record says what was decided and why. A request that breaks it gets a push back that cites it.

VALUES

"Pro costs ₹499"

A price or limit has one entity page. The same number typed anywhere else fails zeno check.

GOALS

"Weekly actives up"

Metrics have written definitions. The gate asks which metric a request moves, and calls it unproven if none.

PRINCIPLES

Company rules C-20+

We add our own principles next to zeno's. Each verdict cites them by ID.

DATA

Read-only facts

A source page names the tool that holds the data. The gate queries it to back or reject a claim.

PLANS

Features and tasks

The gate checks whether work is already planned, built, shelved, or in progress elsewhere.

Code standards

A broken standard is a failed build, not a review comment.

$ zeno check checkout 3 errors, 1 warning ✗ architecture no-ui-to-db (1): src/screens/Cart.tsx → src/db/client.ts ✗ canonical-values .context/wiki/surfaces/paywall.md ₹499 stated here but held by no entity page ✗ wiki-frontmatter .context/wiki/decisions/0007.md missing sections: Consequences ! standards-copies .context/wiki/CLAUDE.md 92% copy of zeno standards/wiki-schema.md — replace with a pointer 1 product · 3 errors · 1 warning

Illustrative output in zeno's real format. Repo, files and rule names are made up.

  • Same check, everywhere. On a laptop and in CI.
  • Turning a check off needs a written reason, and the reason shows in every run.
  • One home per standard. Copies of a rule in a repo are flagged.
  • Reviewers stop leaving style and layout comments.
