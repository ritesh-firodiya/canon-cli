PDLC · before AI, with AI, with zeno

AI sped up code.
Review became the wall.

Agents write more code than people can review. zeno moves the checks a machine can do to before the review, so people review less and catch more.

What changed

More code, same reviewers.

Before AI: writing code took time, and so did review. They moved at the same pace.

With AI: teams with high AI use merged 98% more PRs, and review time went up 91%. PRs got 154% bigger.

With zeno: code stays fast. Rules, decisions and standards are checked before review, so people review less by hand. This is the target the pilot measures, not a result yet.

"With AI" numbers: Faros AI, AI Productivity Paradox, 2025, telemetry from 10,000+ developers on 1,255 teams. Before-AI bars are the baseline. The zeno bar is a target, not data.

Why review is the wall

Reviewers check by hand what a machine could check.

A reviewer today checks
  • Is the logic right?
  • Is this what the product needs?
  • Does it follow our standards and layout?
  • Does it cross an architecture boundary?
  • Does it undo a past decision?
  • Does a price or limit now have two values?
  • Was the reason for it ever true?
With zeno, a reviewer checks
  • Is the logic right?
  • Is this what the product needs?

The other five run before review:

zeno check covers standards, layout, architecture and values with two homes. The weigh gate covers past decisions and the claims behind the request.

zeno shows up at every stage, not just in review.
