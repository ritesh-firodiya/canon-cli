Pilot proposal · 4 weeks · 3 repos

Decided things
stay decided.

AI agents write code fast. zeno makes sure they follow the decisions we already made, and stop when a request rests on a guess.

zeno · open source (MIT) · CLI + Claude Code plugin
The problem

Agents are fast. They don't remember what we decided.

  • Re-opened decisions. An agent brings back an approach the team already dropped.
  • Two copies of a fact. A price, limit or rule gets a second, different value.
  • Guesses get built. "Users want this" turns into code before anyone checks it.
  • Rules drift. Every repo has its own rules file, and they stop matching.
How it works

Every non-trivial request passes a gate before work starts.

Each verdict cites the rule or decision it used. When someone overrides a push back, the reason is logged in the repo, and zeno learn suggests rule changes from those logs.

Facts, not assumptions

A request is not a fact. Each claim in it gets checked.

The gate reads data only through tools we already use (MCP, CLI). It runs one or two small read-only queries, and keeps counts, not people.

Company standards

Write a rule once. Every repo gets it. Overrides are visible.

Lives in git

Rules and decisions are files in our repos. They get reviewed, versioned and blamed like code. No new database.

Checked, not just written

zeno check fails a PRD with a missing section, a stale page, or a price with two homes.

Works with our tools

It doesn't replace Copilot, Confluence or our CI. It adds the check they don't have.

Where it fits

Many tools give agents context. Few enforce decisions.

Copilot org instructions give one set of rules to every repo. Nothing checks that work follows them.

Wiki and Q&A tools (AutoWiki, DeepWiki, Unblocked) describe code and find context. They don't block anything.

Qodo gates code quality, not product decisions.

zeno sits beside them and adds the missing step: stop work that breaks a decision.

The pilot

4 weeks · 3 repos · 1 person · on a branch

Out of scope: a hosted site, an editor, other people's laptops, CI changes on main, new paid services, and data going anywhere it doesn't already go.

Risks and safeguards

Small, local, and easy to undo.

Our data

zeno runs no servers and sends nothing itself. The gate runs inside Claude Code, so it's only used where Claude Code is already approved.

Our repos

All zeno files sit on a branch. Nothing merges without the repo owner's OK.

Slower work

Time cost is measured. If the gate costs more than it saves, the pilot fails, and we say so.

Wrong verdicts

Every verdict cites its source, so a wrong one is easy to spot. Overrides are logged, and zeno learns from them.
